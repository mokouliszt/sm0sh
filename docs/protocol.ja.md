# メールボックス仕様（ABI 1）

このデバイスマップはsm0sh固有。MELSEC CPUの特殊リレー・特殊レジスタの意味とは
独立している。SLMPのデバイスコードを通信上のアドレスとして利用する。

## ワイヤ形式

| 項目 | 対応 |
| --- | --- |
| フレーム | 3Eバイナリ、要求`50 00`、応答`D0 00` |
| 通信 | TCP（既定）、UDP、両方を設定で選択 |
| コマンド | 一括読出し`0x0401`、一括書込み`0x1401`、ブロック読出し`0x0406`、ブロック書込み`0x1406` |
| サブコマンド | ワード`0000/0002`、ビット`0001/0003` |
| Q/Lデバイス指定 | 3バイトの先頭番号 + 1バイトのコード |
| iQ-Rデバイス指定 | 4バイトの先頭番号 + 2バイトのコード |
| コード | D=`A8`、W=`B4`、SD=`A9`、SM=`91`、SW=`B5` |
| 数値のバイト順 | リトルエンディアン |
| ビットのパッキング | 1バイトに2点。先の点が上位ニブル。SM0 ONの1点書込みは`10` |
| 一括アクセスの上限 | ワード960点、ビット7168点。領域の実サイズ制限も適用 |

ネットワーク番号・PC番号・ユニットI/O番号・局番号は応答に引き継ぐ。
他局への転送は行わない。通常の接続値は `00 FF FF 03 00`。
監視タイマ値はフレームの一部として受信するが、コマンドの実行時間制限には使わない。
SLMP応答は受付後すぐに返し、実行時間は`command_timeout_ms`で制限する。

TCPの分割・連結受信を扱う。1フレームのヘッダから本文までを接続タイムアウト内に
受信できなければ切断する。ヘッダが不正、または本文長が6〜4096バイトの範囲外でも切断する。
ヘッダを解釈できた要求の本文が不正な場合は終了コードを返す。
UDPは1データグラムに完全な1要求が必要。不完全・過長・余剰データ付きの要求は破棄する。

## ブロックアクセス

ブロック読出し（`0406`）とブロック書込み（`1406`）は、
サブコマンド`0000`（Q/L）と`0002`（iQ-R）に対応する。
ブロックアクセスでは`0001`・`0003`を使わない。

要求データの先頭に、ワードデバイスのブロック数とビットデバイスのブロック数を各1バイトで置く。
ワードデバイス（D/W/SD/SW）の全ブロック、ビットデバイス（SM）の全ブロックの順で指定する。
各ブロックは先頭デバイス番号、デバイスコード、2バイトの点数で表す。
デバイス指定形式と数値のバイト順は一括アクセスと同じ。
SMの1点は16ビット分であり、1ビットではない。

読出し要求にはブロックの指定だけを並べる。
応答にはブロックごとのヘッダを付けず、要求順にデータを連結して返す。
SMも16ビットを1ワードにまとめる。
書込み要求では、各ブロックの指定の直後にそのブロックのワードデータを置き、
その後に次のブロックを指定する。SMの書込み値もニブル形式ではなくワード形式とする。

| 上限 | Q/L（`0000`） | iQ-R（`0002`） |
| --- | --- | --- |
| 合計ブロック数 | 1〜120 | 1〜60 |
| 読出しの合計点数 | 960点以下 | 960点以下 |
| ブロック指定分を含む書込み点数 | `合計点数 + 4 × ブロック数 <= 960` | `合計点数 + 9 × ブロック数 <= 960` |

各ブロックは1点以上とし、割当済みのデバイス範囲内に収める。
上限はSLMPリファレンスマニュアル SH-080956ENG-MのRead Block・Write Blockに従う。

書込み先はD/Wと、最大1つのSMブロックに限る。
SMブロックは先頭SM0・1ワード・値`0x0000`または`0x0001`とし、SM1〜SM15は書き換えない。
全ブロックを検証してから書き込むため、後ろのブロックが不正な場合も一部だけを更新しない。
その場合、前回の結果を消去せず、コマンドも起動しない。
D/Wの範囲が重なる場合は、要求内で後ろのブロックの値を採用する。
SM0の操作はD/Wの更新後に行うので、D/Wの準備と実行を1要求にまとめられる。
SM0がONの間の書込みは、従来どおり`0xCEE0`で拒否する。

読出しは1つのメールボックスロック内で全ブロックを取得する。
例えばSW0〜SW7とSD0〜SD951は合計960ワードで、1要求に収まる。
SDの範囲は送信前に決める。同じ応答で返るSWのログ長に合わせて、その要求の点数を変えることはできない。
単一実行とSDリセットの規則は、ブロックアクセスでも同じ。

## DとW

既定はDが8192ワード、Wが128ワード。

1. `argv[0]`（実行ファイル名）をD0から格納する。
2. 文字はUTF-8。1ワードの下位バイト、上位バイトの順でバイト列にする。
3. 文字列要素ごとにワード境界まで0で埋める。次の要素は次のワードから始める。
4. `W[i]`に`argv[i]`の**最後のDの番号（含む）**を入れる。
5. 最後の要素の次のWに`65535`（`0xFFFF`）を入れる。

要素0の先頭はD0。要素iの先頭は`W[i-1] + 1`。
コマンドID、要素数ヘッダ、固定長の引数スロットは使わない。
Wの終端D番号は狭義単調増加し、Dの割当範囲内でなければならない。

空の引数は1ワードの0を割り当てる。末尾の0バイトは除去し、要素内部のNULはエラーにする。
末尾の空白は除去しない。実行ファイル名の空文字列、W終端マーカーの欠落、
範囲外や逆順の終端番号、不正UTF-8は実行時の入力エラーとなる。

Wはデバイス表記が16進で、W9の次はWA、WFの次はW10。
格納する終端番号はDの0起点インデックス。たとえばD100の終端値は整数100（`0x0064`）。
`0xFFFF`をマーカーに予約するため、Dは最大65535ワード（D0〜D65534）。
Wは2〜1024ワードに設定可能で、最後のマーカー用に1ワード残す。

毎回Wのマーカーまで書くこと。前回のWが残っていても、そのマーカーより後ろは解釈しない。
大きいDデータは960点以下に分割して書く。最後の書込みの応答を確認してからSM0をONにする。

## SM

SMは16点を割り当てる。

| デバイス | 意味 | PLCからの操作 |
| --- | --- | --- |
| SM0 | 受付済み／実行中 | アイドル時だけON要求可 |
| SM1 | 完了（次の受付まで保持） | 読取りのみ |
| SM2 | 異常完了 | 読取りのみ |
| SM3 | タイムアウト | 読取りのみ |
| SM4 | ログ切詰め | 読取りのみ |
| SM5〜SM15 | 予約、常にOFF | 読取りのみ |

実行要求はSM0への1点ビット書込みを推奨する。
SM0を先頭とする1ワード読出しはSM0〜SM15を16ビットにまとめて返す。
SM0先頭の1ワード書込みで値0または1も受け付けるが、上位15ビットは書き換えない。
それ以外のSMワード書込みは受け付けない。

SM0がOFFのときにON要求を受け付けると、1回のメモリ操作で次を行う。

- 割り当て済みSD全域を0にする。
- SM1〜SM15と前回の結果情報をリセットする。
- 実行番号を1増やし、SW0を実行中にしてSM0をONにする。
- 現在のD/Wからコマンドと引数を確定して実行キューに渡す。

実行中のD/W書込みとSM0へのON/OFFは`0xCEE0`で拒否する。
これらの拒否は実行中のログ・フラグをリセットしない。
アイドル中のSM0 OFF書込みは何もしない。ネットワーク経由のキャンセル操作はない。

終了時はSD、SW、SM1〜SM4を更新してからSM0をOFFにする。
入力エラーや起動失敗でもこの完了処理を行う。
高速なコマンドではPLCがSM0のONを観測する前に完了し得るため、
SM1または実行番号とSW0でも完了を判定できる。

## SW

SWは8ワード、すべてPLCからは読取り専用。

| デバイス | 内容 |
| --- | --- |
| SW0 | 下表の実行状態 |
| SW1 | プロセス終了コード。取得できない場合は`0xFFFF` |
| SW2 | 終了シグナル番号。通常終了・取得不能の場合は0 |
| SW3 | SDログのバイト数、下位16ビット |
| SW4 | SDログのバイト数、上位16ビット |
| SW5 | 実行番号、下位16ビット |
| SW6 | 実行番号、上位16ビット |
| SW7 | メールボックスABIバージョン。現在1 |

| SW0 | 意味 |
| ---: | --- |
| 0 | 初期状態 |
| 1 | 受付済み／実行中 |
| 2 | 正常終了（プロセス終了コード0） |
| 3 | プロセスが非0またはシグナルで終了 |
| 4 | D/Wからコマンドを解釈できない |
| 5 | 実行ファイルを起動できない |
| 6 | 実行時間超過 |
| 7 | サービス停止などによる中断 |
| 8 | 出力取得・プロセス待機などのI/Oエラー |

実行番号は起動時0、要求受付ごとに加算し、32ビットで周回する。再起動を跨いだ一意IDではない。
シグナル終了やタイムアウト時はSW1だけで判定せず、SW0とSW2も参照する。

## SDログ

既定は8192ワード。stdoutとstderrを同じストリームに流し、受信順に保存する。
プロセス側のバッファリングによって実際のイベント順と出力順が異なることはある。
標準入力は`/dev/null`。

出力をUTF-8として扱い、不正バイトやNULは置換文字に変換する。
末尾には必ずNUL用の空きを残す。最大バイト数は`sd_words * 2 - 1`。
UTF-8の文字途中では切らず、切詰めた場合はSM4をONにする。
切詰め後もプロセスの出力を読み捨てるので、出力容量超過だけでプロセスを停止させない。

ログの確定まではSD全域が0。リアルタイムで追記されるログ領域ではない。
次の受付まで結果を保持する。次の要求の受付はログの読出しを待たないため、
送信元は1台とし、結果取得完了後に次の要求を送る。

読出し手順はSW0〜SW7を一括取得し、完了状態を確認してから、
`SW3 + (SW4 << 16)`バイト分のSDを960点以下に分割して読む。
最後にSW5/SW6が同じか確認すれば、読取り中の結果置換を検知できる。
空ログは0バイトで、SD読出し要求自体が不要。

## 終了コードと再送

| SLMP終了コード | sm0shでの意味 |
| --- | --- |
| `0000` | デバイス操作を受け付けた |
| `C050` | 本文長・書込みデータ長などが不正 |
| `C051` / `C052` | ワード点数／ビット点数が不正 |
| `C056` | 割当範囲外 |
| `C059` | コマンド／サブコマンド非対応 |
| `C05B` | デバイス種別・アクセス方法・書込み先が非対応 |
| `C060` | ビットデータのニブル値が不正 |
| `CEE0` | 実行中、または実行処理を利用できない |

SM0の書込みが`0000`でも、コマンドが正常終了したとは限らない。
プロセスの結果はSWとSDで判定する。

3E要求に実行の重複を排除するIDはない。接続断や応答紛失の後に実行要求を
機械的に再送しない。SWの実行番号と状態を確認し、業務側で再実行可否を決める。

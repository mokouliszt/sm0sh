# ADR 0001: 単一クレートと責務ごとのディレクトリ

## 状態

採用

## 背景

sm0shはUbuntu上で動作する1つのサーバーアプリケーションである。
プロトコルの変更、デバイス仕様の変更、Linuxのプロセス制御の変更を、
それぞれの担当箇所で扱える構成にする。規模に対して構成や依存関係を増やしすぎない。

## 決定

アプリケーションは単一のCargoパッケージとし、次の構成にする。

| パス | 責務 |
| --- | --- |
| `src/` | サーバー本体。責務ごとにファイルを分ける |
| `tests/` | メールボックス、プロセス実行、実ソケットの結合テスト |
| `tests/reference_rust/` | 参考Rustクライアントを使う独立した検証用パッケージ |
| `examples/` | そのまま試せる設定例と依存パッケージ不要のPythonクライアント |
| `deploy/` | Ubuntu向けのサービス設定と導入スクリプト |
| `docs/` | デバイス仕様、運用手順、参考資料、検証結果 |
| `docs/adr/` | ディレクトリ構成を含む設計判断とその理由 |
| `.github/workflows/` | Linux向けの継続的なビルド・検証 |

`src/`内では次の境界を設ける。

| モジュール | 責務 |
| --- | --- |
| `protocol` | SLMPフレームの検証、デコード、応答のエンコード |
| `memory` | デバイス値とメールボックスの状態遷移 |
| `command` | D/Wとコマンド・引数の相互変換 |
| `executor` | Linuxプロセスの起動、出力取得、終了処理 |
| `server` | ソケット、接続の受付、要求の配送 |
| `config` | 起動設定の読み込みと検証 |
| `main` | CLIと終了シグナルの受付 |

プロトコルのデコードはメモリ更新やプロセス起動を行わない。
Linux固有の処理は`executor`に集め、デバイスの状態遷移から分離する。
本番アプリケーションで使うクレートを増やすのは、別の利用元や独立した公開APIが
実際に必要になった場合とする。検証用パッケージは本体の実行時依存に含めない。

## 影響

通常の機能追加では、既存モジュールの責務に沿って修正できる。
層を表すためだけのディレクトリや抽象化は追加しない。
デバイス仕様の正本は[protocol.md](../protocol.md)とし、
設計理由と具体的なレジスタ定義を重複して管理しない。

関連する判断は[メールボックスABI](0002-mailbox-abi.md)、
[プロセス実行](0003-process-lifecycle.md)、
[検証と配布](0004-validation-and-distribution.md)に記録する。

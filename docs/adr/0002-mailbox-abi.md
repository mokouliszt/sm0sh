# ADR 0002: D/Wで区切る文字列と単一実行メールボックス

## 状態

採用

## 背景

PLCからコマンド名と可変長の引数を文字列で渡す。
文字列の境界を曖昧にせず、PLCからの書込みとUbuntu側の実行が競合しないようにする。

## 決定

DにUTF-8のコマンドと引数を下位バイトから格納し、
Wの各要素に対応する文字列の終端D番号（そのDを含む）を格納する。
最後の要素の次に`65535`を置く。要素ごとにワード境界まで0で埋め、
空の引数にも1ワードを割り当てる。

コマンドと引数はそのままOSへ渡し、シェルの引用符や演算子を再解釈しない。
シェル構文が必要な場合は`/bin/sh -c`を明示的に指定する。

1つの共有メールボックスで同時に実行するのは1件とする。
SLMPの1操作全体を同じロックで保護する。
SM0の受付時にSD全域と完了情報をリセットし、現在のD/Wから実行内容を確定する。
実行中の書込みは拒否し、完了時はログと状態を公開してからSM0をOFFにする。
ソケット通信やプロセスの待機中は、メモリのロックを保持しない。

SLMPの終了コードはデバイス操作の受付・拒否を表す。
受付後の文字列解釈、起動、プロセス終了、タイムアウトの結果はSWとSDで表す。
不正な要求でメモリの一部だけを更新しない。
ブロック書込みでも全ブロックを検証してからD/Wを更新し、SM0は最後に処理する。
これにより、D/WとSM0をまとめた要求が、更新前のコマンドを起動することを防ぐ。
SM0を複数指定した要求は拒否し、D/Wの重複範囲は要求順に更新する。
ブロック読出しも同じロック内で全領域を取得し、状態とログの世代を揃える。
SDと状態フラグはPLCから読取り専用とする。
再起動時にデバイス値を初期化し、自動再実行は行わない。

## 影響

PLC側は要素ごとの終端番号で引数を指定できる。
複数回に分けたD/Wの準備から結果の取得までは、書き手を1台にする必要がある。
実行要求への応答が失われた場合は、状態を確認してから再送を判断する。

メールボックスABIの互換性はアプリケーションのバージョンと分けて管理する。
具体的なバイト順、範囲、状態値は[protocol.md](../protocol.md)を参照する。

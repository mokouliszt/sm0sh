# ADR 0003: プロセスの寿命と出力取得の上限

## 状態

採用

## 背景

外部コマンドは大量に出力したり、終了しなかったり、子プロセスを残したりする。
コマンドの状態にかかわらずSLMP要求を扱い続けられるようにする。

## 決定

フレーム長、要求点数、接続数、実行時間、保存する出力に上限を設ける。
運用で変更する上限と環境変数は起動設定にまとめる。
接続先は初期設定ではloopbackとし、接続元IPを明示的に許可する。

stdoutとstderrを同じストリームから取得し、保存容量を超えた分は読み捨てる。
ログはUTF-8の文字途中で切らず、切詰めを状態フラグで通知する。
標準入力は`/dev/null`とする。

起動したコマンドにプロセスグループを割り当てる。
時間超過、サービス停止、親プロセスの先行終了時は、通常の子プロセスも終了させる。
systemdのサービス停止では`KillMode=control-group`も利用する。

## 影響

出力容量を超えただけではコマンドを停止させず、出力による待ち合わせを防げる。
許可した接続元は、サービスの実行ユーザー権限でコマンドを起動できる。
IP制限は認証ではなく、プロセスグループもコマンドの隔離環境ではない。
別セッションへ移るプログラムまでコマンド単位で隔離する設計にはしない。

実際の設定値とサービスの権限設定は[ubuntu.md](../ubuntu.md)を参照する。

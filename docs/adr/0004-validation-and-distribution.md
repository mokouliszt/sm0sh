# ADR 0004: 独立クライアントによる検証と配布物の分離

## 状態

採用

## 背景

通信プロトコルは、自前のクライアントとサーバーが同じ誤りを持つと検知しにくい。
ビルド環境や参考実装を、アプリケーションの実行時に要求しない構成にする。

## 決定

既知のフレーム値、実ソケット、プロセスの起動・終了を使って外部から見える挙動を検証する。
テストは空きポートと有限の待機時間を使う。
ABI変更時は状態遷移と少なくとも1つの独立したクライアントとの通信を確認する。

参考クライアントは本体へ組み込まず、独立した検証に使う。
Rust用の検証パッケージは`tests/reference_rust/`へ置き、参考リビジョンを固定する。
sm0sh固有の書込み可能なSM0を扱うため、参考クライアントでは公開のraw APIを使う。
同梱のPython例は依存パッケージ不要とし、D、Wの終端までの表、SM0の順で送る。

`docs/protocol.md`をメールボックス仕様の正本、`docs/validation.md`を実測結果の記録とする。

CIはCargo.lockを使ったビルド、書式、静的チェック、テストを行う。
権限は読取りを基本とし、検証とパッケージ公開は別の操作にする。
配布物にはソース、実行に必要な設定例、運用手順、ライセンスを含め、
認証情報、ツールチェーン、ビルドキャッシュは含めない。

Ubuntu向けの導入は`deploy/`で扱う。
専用の非ログインユーザーと作業ディレクトリを使い、設定は管理者所有とする。
再インストール時は既存設定を保持し、サービスの有効化・起動は管理者の操作で行う。

## 影響

通常の実行にはRustツールチェーンや参考クライアントをインストールせずに済む。
ビルドと検証の依存は開発時に限定できる。
